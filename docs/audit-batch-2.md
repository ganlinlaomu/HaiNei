# 第二批：启动与数据可靠性（A08–A11）

保留 `4616611` 的第一批推播授权、HTTP 内容绑定和写入重试，继续以下修正：

- 登录先读本机资料，snapshot 后台恢复；请求的十秒 deadline 包括 response body。账号及 session generation 在签名、解密、恢复和排程回调中检查。远端更新后强制刷新本机 store，避免同账号 `load()` 提前返回。
- transport/logical/discard 去重集合限制 4096 项，互动去重同样有界；数据库唯一键继续承担持久去重。
- 授权暂存单账号最多 500、单发送者最多 25、单条 JSON 最多 64KiB、原始暂存时间 TTL 七天。重复审查不延长 TTL。每次读 50 条，按稳定 ID 最多十页，让后面的发送者也能被审查。达到容量的未决消息拒绝继续占用磁盘，不淘汰已保存消息；它仍可能需要 relay 重送。
- 聊天首次 50 条，历史固定最多 100 条；游标为 createdAt+id，同秒不会遗漏。默认消息恢复只取最近 200 条与各对话最新摘要。新增 messageClass 索引，保证被新互动挤出最近页的旧私信仍能出现在对话列表。
- 未读缓存和消息插入处于同一事务。可见私信的缓存包括好友授权窗口、删除／隐藏偏好和已读游标；它的热路径随新消息增量更新，策略变化时重算。首次／修复后的重算仍需扫描未读范围；搜索和显式修复保留全历史能力。
- 推播授权替换使用一个 D1 batch 事务，避免并发刷新将删除与插入交错；fanout 不再启动超过二十秒预算的新发送工作，正在发送的请求仍受独立 timeout。远端策略采用最后完成写入的请求，跨设备同时编辑仍需后续快照收敛。
- 推播 payload 只添加散列账号 scope 和设备相关 notificationId；Service Worker 持久去重最近 256 个通知，忽略非当前 scope。后台角标是提示点；前台用本机真实未读数校正，锁定／退出清空 scope。散列 scope 可由已知公钥计算，不能声称匿名身份。
- 普通正文只在 durable write 后进入 UI；好友控制仍通过自身持久化流程恢复授权。首页历史分页过滤互动、回执及控制消息。

`npm run typecheck && npm test` 覆盖真实 fake-indexeddb 仓库操作、同秒分页、可见未读缓存、暂存 TTL／容量／后续页，以及跨 Service Worker 重启的通知去重。这里不是 iPhone 原生 IndexedDB 性能测量；1万／5万／10万与 p95 目标仍需真机 trace。

数据库版本升为 14，升级补 messageClass 并建立稳定分页索引。可以回滚第二批 UI／查询逻辑，但需保留支持 version 14 的 Dexie schema，不能让旧版本以 version 13 打开已升级数据库。暂存容量限制为有意的保留策略，不会删除 durable syncedMessages。
